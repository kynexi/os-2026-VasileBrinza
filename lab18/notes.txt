1. Without the semaphore lock, output from different processes is mixed because each character is written in a separate system call. The scheduler can switch processes between writes.

2. The critical section in mix.c is the code between sem_down(3) and sem_up(3), where a process prints its entire line.

3. The while loop in sem_down is necessary because a process can wake up even if the semaphore value is still zero. Another process may acquire the semaphore first, so the condition must be checked again.

4. The spinlock must be released before calling sleep. Otherwise, a process could sleep while holding the lock, preventing sem_up from acquiring it and waking the waiting process. This could cause a deadlock.

Lab 18 — Build a User-Level Thread Switch

1. What exactly does thread_switch save and load?

thread_switch saves the current thread's 14 callee-saved registers: ra, sp, and s0 through s11. It stores them in the old thread's context using offsets from 0 to 104 bytes. It then restores the same registers from the new thread's context.

2. Why is ra the register that makes execution continue in the other thread?

ra stores the return address. When thread_switch restores ra and executes ret, the processor jumps to that address. For a newly created thread, ra is initialized to the thread function, so its first switch starts executing that function. For a previously running thread, ra resumes execution where it was suspended.
